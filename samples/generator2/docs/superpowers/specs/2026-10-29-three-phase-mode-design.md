# Режим «3-фаза» (по мотивам restim)

Дата: 2026-10-29

## Зачем

В [restim](https://github.com/diglet48/restim) (локальная копия `H:\restim-master\restim-master`)
есть трёхфазный режим для обычного аудиовыхода: стерео-джек, три электрода (L, R и общий провод
N). Ощущение «перемещается» между электродами. Управляет этим точка в круге, а готовые паттерны
водят её по траекториям. Пользователю интересна именно эта часть — круг, точка, паттерны и
калибровка. Funscript, сенсоры, Sync Media, импульсный режим и железо FOC/NeoStim не нужны.

Сейчас в приложении CHL и CHR — два **независимых** генератора с собственными фазами. Трёхфазке
нужна одна несущая на оба канала с управляемым сдвигом фазы между L и R. Поэтому это отдельный
режим рендера, а не ещё одна карточка-модуляция.

## Цели

- Отдельный режим «3-фаза»: синус одной частоты и громкость, положение точки (alpha, beta)
  превращается в L/R по математике restim без изменений.
- Все 16 паттернов restim и ручной режим «Палец».
- Скорость и амплитуда паттерна.
- Калибровка: A/B/C power [dB] и Center reduction [%] — как на вкладке 3-phase в restim
  (интерфейс «Modern»).
- Экран с кругом, треугольником, метками Neutral / L+ / R+ и точкой, которая движется в
  реальном времени.
- Настройки режима сохраняются в пресеты.

## Не цели

- Формы несущей, AM, FM, мастер-громкость и морф внутри 3-фазы — только синус.
- Adjust limits (поворот, зеркало, пределы, map to edge).
- Классический интерфейс калибровки (neutral / right в дБ) в UI — внутри используется, наружу
  не показывается.
- Funscript, T-code, сенсоры, Sync Media, импульсный (pulse-based) режим, 4-фаза.
- Отображение режима в редакторе нод и скриптах.

## Анти-цели (провал, даже если «работает»)

- Щелчок или скачок громкости при включении режима, смене паттерна или изменении калибровки.
- Амплитуда любого канала больше 1.0 или больше потолка усилителя `maxVolume0/1`.
- Сломанные старые пресеты: файл без новых ключей обязан открываться как раньше, режим выключен.
- Выпадения звука: рендер блока в 3-фазе не тяжелее рендера двух обычных каналов, и в аудиопотоке
  нет аллокаций.

## Как это работает (справка для исполнителя)

Электроды: N (верх круга, Neutral), L (низ-лево, L+), R (низ-право, R+). Аудиоканалы:
`L = V_N − V_L`, `R = V_N − V_R` — общий провод джека и есть N.

Проверено на коде restim (калибровка 0, синус):

| Точка (alpha, beta) | Ампл. L | Ампл. R | L и R | Лиссажу (X=L, Y=R) |
|---|---|---|---|---|
| Neutral (1, 0) | 0.866 | 0.866 | в фазе | диагональ `/` |
| Низ (−1, 0) | 0.5 | 0.5 | противофаза | диагональ `\` |
| L+ (−0.5, +0.866) | 0.866 | 0 | — | горизонталь |
| R+ (−0.5, −0.866) | 0 | 0.866 | — | вертикаль |
| Центр (0, 0) | 1.0 | 1.0 | сдвиг 60° | эллипс |

На краю круга сигнал однофазный: ток идёт между одним электродом и двумя другими. Внутри круга
поле вращается, в центре все три электрода равны.

## Математика (порт один в один)

Источник — `stim_math/threephase.py`, `stim_math/transforms.py`,
`qt_ui/three_phase_settings_widget.py`.

### На каждый сэмпл (C++)

```
// позиция: линейная интерполяция контрольных точек блока
r = sqrt(alpha² + beta²)
if (r > 1) { alpha /= r; beta /= r; r = 1 }

t11 = (2 − r + alpha) / 2
t12 = −beta / 2           // знак как в restim, вместе с их TODO — не «исправлять»
t22 = (2 − r − alpha) / 2

x = cos θ,  y = sin θ     // θ — фазовый аккумулятор несущей
a = t11·x + t12·y
b = t12·x + t22·y

L = K00·a + K01·b
R = K10·a + K11·b

g = volume · (1 − c·(1 − r))     // c = center reduction / 100
L *= g · maxVolume0
R *= g · maxVolume1
```

### Матрица K (Kotlin, пересчёт только при изменении калибровки)

```
T  = (potential_to_channel_matrix @ ab_transform)[:2, :2] / sqrt(3)
Hw = ThreePhaseHardwareCalibration(neutral_dB, right_dB):
       transform = generate_transform_in_ab()              // 3×3
       C = P @ ab @ transform @ ab_inv @ P_inv · scaling_contant(transform)
K  = C[:2, :2] @ T
```

### Калибровка из UI

- A/B/C power [dB] → `a = 10^(A/10)` и т. д. → `intensity_ratio_to_ud_lr(a, b, c)` → `(neutral_dB,
  right_dB)` → `Hw`. Нужно портировать `calibration_matrix_from_electrode_intensities` вместе с
  `split_point`, а `np.linalg.lstsq` для системы 3×2 заменить решением нормальных уравнений 2×2.
  Затем портировать `calibration_matrix_to_ud_lr` и `inverse_scale_in_arbitrary_direction`.
- Center reduction [%] → `c = reduction / 100`. Формула `g` выше — упрощённый
  `ThreePhaseCenterCalibration` для `ratio = 1 − c ≤ 1`.

Всё это чистый Kotlin без Android, покрывается JVM-тестами (см. «Проверка»).

## Паттерны

Источник — `qt_ui/patterns/threephase/*.py`. Контракт:

```kotlin
interface ThreePhasePattern {
    val name: String
    fun reset()
    /** Сдвинуть время на dt (уже умножено на скорость), результат в alpha/beta. */
    fun update(dt: Float)
    val alpha: Float
    val beta: Float
}
```

- Результат возвращается через поля, а не `Pair`: `update` вызывается в аудиопотоке, аллокации
  там запрещены.
- Амплитуда умножается снаружи, одинаково для всех паттернов (в restim она вшита в каждый —
  нормальный рефакторинг).
- Порт формул буквальный, включая константы и `np.clip`. `np.sin/cos` — `kotlin.math` в Double
  внутри и Float наружу: время растёт, и во Float фаза за час «поплывёт».
- Нормализация в единичный круг делается в рендере, а не в паттерне: Orbiting Circles и Deep
  Throb выходят за 1.0 по задумке.

Список (имена как в restim): Circle, Butterfly Curve, Deep Throb, Figure 8, Jerky Stroke,
Lightning Strike, Micro Circles, Orbiting Circles, Tri-Phase panning (ᴒ), Tri-Phase panning (∧),
Random Walk, Rose Curve, Spirograph, Tremor Circle, Vertical Oscillation, W Shape.

Подводные камни порта:

- **Внутренняя скорость.** restim создаёт паттерн с дефолтами конструктора и зовёт
  `update(dt · velocity_пользователя)`, а паттерн ещё раз умножает на свой `self.velocity`. У
  Panning1/2 он 0.5, у остальных 1.0. Этот множитель сохраняется константой внутри паттерна.
- **Амплитуда.** Panning2 в restim амплитуду игнорирует. При порте амплитуда применяется
  снаружи ко всем одинаково.
- **Члены, зависящие от частоты вызова.** restim зовёт паттерны 60 раз в секунду, а у нас
  вызовов ≥ 500 в секунду. Random Walk на каждый вызов делает `pos -= pos · 0.003` без `dt`, так
  что при порте притяжение к центру пересчитывается на время паттерна: множитель
  `(1 − 0.003)^(dt · 60)`, где `dt` уже умножен на скорость. При скорости 1 это совпадает с
  restim, при другой скорости траектория просто идёт быстрее или медленнее. Остальные 15 паттернов проверены: всё у них зависит от
  накопленного времени, такого нет. Эталоны для тестов генерировать с `dt = 1/60`.
- **Без аллокаций при смене.** Все 17 паттернов создаются один раз при старте. Смена
  паттерна — это смена индекса, который аудиопоток читает раз за блок, и `reset()` выбранного
  паттерна.

### «Палец» (аналог Mouse)

- Палец на круге — точка идёт за пальцем (позиция за пределами круга прижимается к краю).
- Пока палец ведёт, записывается траектория с метками времени.
- Палец отпущен — записанная траектория крутится по кругу в исходном темпе, умноженном на
  скорость. Так устроен Mouse в restim. **Моё решение** — пользователь согласовал только «водить
  пальцем», повтор нарисованного добавлен по образцу restim.
- Меньше двух точек в траектории — точка стоит, где отпустили.
- Смена паттерна стирает траекторию.
- Потоки: касания приходят в UI-поток, читает их аудиопоток. Пока палец на круге, UI пишет
  последнюю позицию в атомарную ячейку (например, два float, упакованные в `AtomicLong`). Когда
  палец отпущен, UI собирает траекторию в неизменяемые массивы и публикует одной
  volatile-ссылкой. Аудиопоток ничего не аллоцирует.
- Касания приходят с частотой 60–120 Гц, поэтому позиция пальца в движке сглаживается фильтром
  первого порядка (~20 мс), чтобы не было ступенек.

### Тактирование

Паттерн считается в Kotlin с контрольной частотой не ниже 500 Гц: блок делится на шаги по
`STEP` сэмплов, `update(STEP / sampleRate · velocity)`. Массив контрольных точек `(alpha, beta)`
длиной `frames / STEP + 1` уходит в C++, там линейная интерполяция. Блоки у пампа длинные (до
~85 мс при 48 кГц), так что одна точка на блок дала бы ступеньки и алиасинг дрожащих паттернов
(Tremor Circle, Lightning Strike).

Первая контрольная точка блока — последняя точка предыдущего, иначе на стыке блоков будет
разрыв.

### Переход между паттернами

**Моё решение:** при смене паттерна позиция плавно переходит от старой к новой за ~300 мс
(линейный кроссфейд координат). В restim точка прыгает мгновенно, а резкий скачок положения — это
резкое изменение ощущения.

## Архитектура

```
UI (Compose)                 ThreePhaseState (StateFlow, пресеты)
   │                                    │
   ▼                                    ▼
ThreePhaseEngine (Kotlin, @Singleton или поле Generator)
   ├─ паттерн + скорость + амплитуда + кроссфейд  → FloatArray контрольных точек
   ├─ калибровка → K (4 float), пересчёт по изменению
   └─ последняя позиция → для точки на экране
   │
Generator.renderAudio()
   ├─ режим 3-фаза выключен → как сейчас (CHL/CHR/моно)
   └─ режим 3-фаза включён  → RenderThreePhase.jniRender(points, K, freq, volume, c,
                                                         maxVol0, maxVol1, bufL, bufR)
   │
AudioMixerPump: route / shuffle / scope / AudioTrack — как сейчас,
                invertL/invertR пропускаются, пока 3-фаза включена
```

- Нативная часть — новый файл `cpp/generator/threephase.cpp` (+ `.h`), добавить в
  `cpp/CMakeLists.txt` рядом с `renderchannel.cpp`. Состояние — один `uint32_t`
  фазовый аккумулятор (DDS, как у каналов). `cos/sin` — таблица синуса на 1024 точки с
  линейной интерполяцией, четверть периода — сдвиг индекса.
- Параметры, которые меняются из UI (частота, громкость, калибровка), читаются один раз на
  блок. Плавность громкости внутри блока — линейная рампа от прошлого значения к новому, чтобы
  движение ползунка не щёлкало.
- `Generator.renderAudio` переиспользует существующие `bufL/bufR`.
- CHL/CHR при включённой 3-фазе не рендерятся, но их настройки и фазы не трогаются: выключил
  3-фазу — каналы звучат как до включения.
- Переключение режима без щелчка: в блоке, где `tp_EN` сменился, рендерятся оба источника,
  первые ~20 мс идёт линейный кроссфейд старого в новый, дальше только новый. Нужен второй
  комплект переиспользуемых буферов.
- Матрица `K` пересчитывается вне аудиопотока при изменении A/B/C (коллектор в духе
  `GeneratorObserver`) и публикуется подменой volatile-ссылки на `FloatArray(4)`.

### Связь с остальным приложением

| Что | В режиме 3-фаза |
|---|---|
| CHL / CHR карточки | скрыты, вместо них карточка 3-фазы |
| Mono | игнорируется (не сбрасывается) |
| invertL / invertR в микшере | пропускаются — инверсия одного канала меняет местами Neutral и низ круга |
| Shuffle | работает — просто меняет местами L+ и R+ |
| Route GEN / MP3 / OFF | работает как сейчас (выбор пользователя) |
| Осциллограф, водопад | работают, берут готовый L/R |
| maxVolume0/1 (Config) | потолок по каналам, как у обычных каналов. **Моё решение.** При разных значениях геометрия перекашивается — это компенсируется калибровкой A/B/C |

## UI

**Моё решение по размещению:** в `TopBarAudioSource` добавляется кнопка «3Φ» (переключатель,
зелёная, когда включено). На главном экране при включённом режиме вместо `CardCard(CHL)` и
`CardCard(CHR)` показывается карточка 3-фазы. Осциллограф, водопад и MP3Control остаются на
месте.

Карточка 3-фазы, сверху вниз:

1. Круг: окружность, вписанный треугольник, метки Neutral (верх), L+ (низ-лево), R+
   (низ-право), точка текущей позиции. Для паттерна «Палец» — линия нарисованной траектории.
   Квадрат по ширине карточки. Ось alpha смотрит вверх, +beta — влево (как в restim:
   `screen = (−beta, −alpha)·R`).
2. Выпадающий список паттернов («Палец» первым).
3. Скорость: 0.1…10, шаг 0.1, по умолчанию 1.0.
4. Амплитуда: 0…1, по умолчанию 1.0.
5. Частота несущей, Гц (диапазон как у несущей в CardCard).
6. Громкость 0…1.
7. Сворачиваемая секция «Калибровка»: A, B, C power [dB] (−40…+10, шаг 0.1, по умолчанию 0),
   Center reduction [%] (0…20, шаг 0.1, по умолчанию 13.0 — дефолт restim), кнопка сброса.

Точка на экране обновляется с частотой кадров из последней позиции движка. Аудио буферизовано,
поэтому звук отстаёт от точки на длину буфера — для первой версии это допустимо.

Стиль — тёмная тема и компоненты существующих карточек.

## Проверка

- **JVM-тесты математики.** Эталонные значения генерирует Python из restim
  (`H:\restim-master\restim-master\venv\Scripts\python.exe`): `K` для нескольких наборов A/B/C;
  `(L, R)` для `(alpha, beta, θ)`, включая точки из таблицы выше и точки за пределами круга;
  `intensity_ratio_to_ud_lr`. Скрипт генерации кладётся рядом с тестом, числа — в тест. Допуск
  1e-4.
- **JVM-тесты паттернов.** Для каждого из 16 — первые N шагов `update(dt)` против того же
  паттерна в Python (эталонные массивы). «Палец»: запись, повтор, зацикливание, пустая
  траектория.
- **Пресеты.** Старый файл без `tp_*` открывается, режим выключен; сохранение и чтение — те же
  значения.
- **Вручную на устройстве, осциллограф в режиме Лиссажу.** Пальцем в Neutral, низ, L+, R+ и
  центр — картинка совпадает с таблицей. Смена паттерна, движение ползунков громкости и частоты,
  включение и выключение режима — без щелчков.
- Сборка через `gradle-run` (см. память: `python` + `gradlew.bat`).

## Решения, принятые мной (проверить при чтении)

1. Повтор нарисованной пальцем траектории, как Mouse в restim.
2. Плавный переход между паттернами ~300 мс.
3. Кнопка «3Φ» в верхней панели источников; карточка 3-фазы заменяет карточки каналов.
4. `maxVolume0/1` применяются как потолок по каналам.
5. Громкость 3-фазы по умолчанию 0.1, несущая 700 Гц.
6. Диапазоны: скорость 0.1…10, A/B/C −40…+10 dB.
7. Звук в C++, паттерны в Kotlin с контрольной частотой ≥ 500 Гц.
